# 流程验证版 0.1

这个小型可玩原型用于验证静态部署与核心交互是否连贯。它不是完整 MVP，也不把试运行参数写成最终设计决定。原有模块规则、设计决定与待确认清单保持不变。

## 操作

1. 初始背包中有一瓶水与一个生土豆，已装备旧猎刀和帆布背包。点击仓库物品可装包，点击随身物品可回仓或使用。
2. 选择低风险货运站或高风险隧道，点击出发。途中无选择，不允许整理物品或操作机器。
3. 每 2.5 秒自动模拟一个节点，共 6 个节点。补给较低时自动使用，伤害与发现物品由带种子的伪随机数决定。
4. 成功后手动回仓。失败后所有随身内容及装备全损，以低生命值返回；仓库与机器不受损。
5. 仓库初始有一套备用装备。全损后可点击仓库中的猎刀/背包重新装备；没有背包时可使用本版暂定的 2×2 临时口袋探索。这不是最终免费装备或收益承诺。
6. 给土豆盆或滤水器手动投入仓库原料。产物停留在机器独立输出区，需手动领取。仓库空间不足时不会丢失产物。
7. 基地按在线可见页面经过的时间缓慢恢复状态。刷新会保留进度，包括正在进行的探索。关闭页面或切到后台暂停，不实现离线收益。
8. “重置存档”提供确认与取消，不会误点一次就清除进度。

## 已实现与保留边界

| 系统 | 本版实现 | 未实现 / 简化 |
| --- | --- | --- |
| 探索 | 两条示例路线、6 节点自动文字事件、随机伤害与发现、无途中分支 | 正式事件表、战斗、特殊结局、地图解锁 |
| 网格 | 矩形占格、从上到下/从左到右自动放置、FIFO 拾取、放不下保留旧物品、手动转移 | 拖放、旋转、重排、主动换装、价值筛选 |
| 背包/装备 | 帆布背包提供 4×3；背包本体为 2×2；全损后可手动装备备用物品 | 背包升级、途中换包与锁定；不存在嵌套容器 |
| 生存 | 补给占格、自动使用、饥饿或缺水逐步扣血、失败低生命值返回、基地免费缓慢恢复 | 医疗、状态效果、保险 |
| 水循环 | 瓶装水 1×2；饮用后在原位置变为塑料废料 1×1；塑料 1→1 水 | 正式设施建造与配方解锁 |
| 食物 | 肥料 1→3 生土豆，生土豆可食用 | 烤炉、烤土豆、共享热量与指定燃料槽均未实现，未使用替代规则 |
| 生产 | 两台预置机器；独立输入/输出、限量堆叠、缺料或满输出停机 | 自动搬运、设施建设、队列与升级 |
| 时间 | 基地最低 1×；每探索节点推进 30 游戏秒，同时计算生产 | 真时、离线积累、昼夜、列车迁移 |
| 存档 | 当前浏览器 localStorage；版本/形状校验；损坏存档安全回退；存储失败有提示 | 云同步、账户、多存档、迁移/导入导出 |

## 暂定测试参数

这些值仅为短时间验收便利，不解决设计文档中的对应待确认项。

- 主仓库 8×5；帆布背包 4×3；无包口袋 2×2；仓库/背包不堆叠，不旋转
- 水补水 +45，土豆饱食 +25；低于或等于 40 自动使用对应物品
- 每节点饱食 −10、补水 −14；任一为 0 每节点生命 −14，两者不叠加
- 货运站单节点受伤概率 32%、基础伤害 18；隧道 76%、基础伤害 40；猎刀将伤害乘 0.55 后四舍五入
- 全损生命值重设为 12；基地每游戏秒生命 +0.65、饱食 +0.4、补水 +0.5，均不超过 100
- 栽培 20 游戏秒；滤水 16 游戏秒；输入最多 3，输出最多 6；整批输出放不下时不消耗原料
- 所有初始物资与预置设施仅是验证存档，不代表最终新手配置
- 铁废料是占格与拾取测试材料，本版不具有加工用途

## 技术结构

- `index.html`：语义页面与原生弹窗。
- `app/engine.js`：无 DOM 的规则与存档校验；所有数值集中在此。
- `app/main.js`：交互、模拟时钟、浏览器持久化；使用 `textContent` 展示存档字符串。
- `app/style.css`：响应式界面与原创 CSS 列车插画；无外部图像/字体/CDN。
- `tests/engine.test.js`：Node 内置测试运行器，无依赖。
- `tests/browser_smoke.py`：可选 Playwright 冒烟脚本，不参与默认 CI，需测试环境已有 Playwright 与 Chromium。
- `scripts/build.js`：只复制运行时文件到 `dist/`，设计文档与开发文件不进入网页部署产物。
- `.github/workflows/deploy.yml`：检查 → 测试 → 构建 → 官方 Pages artifact → 部署；构建仅 contents:read，部署仅 pages:write/id-token:write。

参考现有个人项目采用纯规则层与界面分离、localStorage、独立测试和明确验证边界的做法。为静态流程测试可靠性，本版选择零构建依赖原生实现，不迁移参考项目的完整框架。

无分析追踪、远程 API、账号或服务端数据。所有应用资源同源、相对路径引用，可用于 GitHub Pages 仓库子目录。直接通过 file:// 打开 ES module 不受支持，请使用 HTTP 静态服务器。

## 验证记录

本地已通过：

- `npm run check`：两个 JavaScript 文件语法检查。
- `npm test`：20 项测试，其中包含 100 个随机种子各重复 3 次外出的存档/状态不变量检查。
- 覆盖矩形空间不足、FIFO 不替换、转移失败原子性、水变废料、机器比例与输入/输出边界、自动探索及恢复、失败全损、备用装备、损坏存档拒绝。
- `npm run build`：生成完整静态产物，入口及所有相对资源存在。

尚未验证：

- 浏览器实际渲染、触屏与键盘完整流程。测试环境的 Chromium socket 启动失败；云浏览器拒绝访问本地 URL，未绕过限制。已提供可执行冒烟脚本，不能将脚本存在当成测试通过。
- GitHub Actions 与线上 Pages 尚未执行/验证；以实际发布记录为准。
- 无完整数值平衡、可访问性审计、跨浏览器兼容性与性能基准。

后续正式发布后，应在真实 Pages 子路径验证：初始界面 → 投料 → 出发 → 中途刷新 → 自动结算 → 手动回仓/领取 → 刷新持久化 → 取消/确认重置，并检查移动端布局与控制台错误。
